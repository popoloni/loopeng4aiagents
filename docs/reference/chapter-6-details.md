### Support outcomes and remaining limits

Use `--case support --support-scenario NAME` for these deterministic branches:

| Name | Expected outcome |
| --- | --- |
| `refund` | First timeline claim rejected, corrected recommendation handed to billing specialist; no financial action |
| `approved` | Same handoff, then simulated human approval and matching confirmed billing receipt; resolved |
| `unconfirmed` | Human approval without billing confirmation; `awaiting_confirmation`, no claim of completed refund |
| `human`, `identity`, `fraud` | Mandatory handoff before account retrieval/disclosure; no reasoning retries |
| `policy` | Stale policy escalates before drafting |
| `repeat_failure` | Same failed timeline signature twice; stop without spending the third attempt |
| `tool_timeout` | One serialized tool resumption preserves account evidence; reasoning retry budget remains separate |
| `tool_exhausted` | Three resumptions exhausted; escalate with collected evidence, no reasoning attempts |

The callable support example also accepts `queue_accepts=False`, which returns `handoff_pending`, not a successful escalation. Receipt tests reject an incorrect charge, amount, unconfirmed action, or wrong fixture source. The fixture's recommendation and response are deliberately structured/templates: this does not evaluate unrestricted natural-language factual claims, tone, completeness, or emotional distress. Clarification stays at zero because these fixtures already contain the needed facts; interactive two-question clarification and a real four-minute wall-clock budget remain intentional gaps. JSON round-tripping demonstrates resumable state but does not provide crash-safe durable storage. No policy exceptions or autonomous refunds are delegated.

Validation uses executable SQLite results, data-dependent reconciliation, current-head check records, risk-policy negative controls, and state-transition assertions. Tests mutate underlying data to reject hardcoded answers and receipts. They also prohibit socket/subprocess calls while running all case functions and check repeated runs for deterministic output. These are fixture contract tests, **not observed benchmarks**; the manuscript's published percentages remain attributed to the original experiments above.
